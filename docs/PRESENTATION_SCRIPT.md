# 答辩讲解稿与问答

## 90 秒项目介绍

本项目针对工业作业现场中安全帽、反光背心佩戴和危险区域入侵难以持续人工监管的问题，设计了一个基于 YOLOv8 与 ByteTrack 思路的智能监测系统。系统先对图片或视频帧进行人员和 PPE 检测，再通过 IoU 跟踪获得稳定的人员编号，使用 PPE 框与人员框的空间关系判断佩戴情况，使用人员脚底中心点与危险区多边形判断越界。连续 3 帧确认和 10 秒冷却机制用于降低视频场景误报。FastAPI 提供登录、推理任务、事件、摄像头、危险区和指标接口，SQLite/PostgreSQL 负责持久化，浏览器工作台用于演示和事件处理。

## 常见问题与回答

### 为什么选择 YOLOv8？

YOLOv8 提供成熟的单阶段目标检测训练和推理接口，适合在有限周期内完成从数据、训练到服务部署的完整工程链路。项目没有把“使用 YOLOv8”包装成未经验证的新模型结构创新。

### ByteTrack 在项目中做了什么？

系统使用人员检测框的 IoU 进行稳定匹配，为相邻帧分配 track_id；规则和冷却键使用 camera_id、track_id、event_type，从而避免同一个人重复告警。

### 为什么 PPE 不是直接和最近的人绑定？

系统要求 PPE 框中心点位于人员框内，并限制 helmet/vest 的人体纵向区域，避免相邻人员或背景物体错误关联。

### 如何判断危险区域入侵？

使用人员框底部中心点进行点在多边形判断。脚底点比框中心更接近“人是否站进区域”的业务含义，边界点按进入处理。

### 这些指标能作为最终结论吗？

E7、E8、E6 和旧集结果都可作为当前实测结论，但必须注明数据版本、训练轮数与 test split；其中 E7 才是当前部署权重。三张 hard-case 原图及其增强、E8 的 150 张 train-only 视频帧只能证明定向回归或训练流程，不能证明独立泛化；80 epoch、300–500 帧独立自建集、正式 GPU 性能和消融实验仍需实际执行。

### 为什么当前没有实时摄像头？

第一版范围限定为图片、MP4 和本地摄像头接口演示，暂不接入 RTSP 和设备控制，避免把未实现能力写进成果。

### 系统如何处理模型缺失？

服务会切换到 deterministic fallback，保证接口和规则演示可进行，同时 `/health` 会明确报告 backend 和 model_available，避免把 fallback 冒充真实模型。

## 结束语

本项目把检测模型、人员跟踪、安全规则、告警持久化和工作台组合成可运行系统，并保留数据、参数和结果的追溯链路。当前已经完成公开测试集评估和已知问题回归，后续以独立真实场景数据、长周期训练、正式性能测量和消融实验继续提高可信度。
